# M3 — Wallet on BSC Testnet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** USDT arrives at a user's own deposit address and is credited on
finality; it sweeps to a hot wallet; and it leaves again through a withdrawal
that an allowlist, a cooldown and a fresh OTP all had to agree to.

**Architecture:** A `chain` module behind two narrow interfaces — a read side
(`ChainClient`) and a sign-and-send side (`Signer`) — so a third-party
custodian can replace the signer later without the ledger changing (PRD §8.1).
Deposits are discovered by a watcher that reads logs **at the finalized head,
never at the chain head**, and credited by the M1 ledger. Nothing writes a
balance; every movement is a balanced journal.

**Tech Stack:** NestJS 11 · viem · @scure/bip32 + bip39 · @nestjs/schedule ·
Drizzle · PostgreSQL 16 · BSC testnet (chain 97) via NodeReal

**Spec:** `docs/PRD.md` — M3 row of §14. Custody §8.1, deposits §8.2, sweeping
and gas §8.3, withdrawals §8.4, buckets §5.2, money rules §5, observability
§13.3, security §13.5.

## Global Constraints

- **Credit on finality, not on a confirmation count.** BSC has deterministic
  fast finality (BEP-126); the watcher reads `eth_getBlockByNumber("finalized")`
  and never the chain head. At the head `eth_getLogs` returns incomplete
  results and ERC-20 deposits are silently missed. (§8.2)
- **A reorg-reversal journal path is still built**, even though finalized
  blocks cannot reorg short of a Byzantine attack. A custodial ledger must be
  able to reverse a credit, and retrofitting that under pressure after an
  incident is exactly the wrong time to write it. (§8.2)
- **No private key ever in the browser, in the database, or in source.** The
  HD seed and the gas wallet key come from the environment only. They are not
  settings and never appear in `system_setting` or an admin screen. (§13.5,
  DEPENDENCIES §2.5)
- **Testnet only.** Every endpoint must report chain id 97. A signer pointed
  at chain 56 is a bug, not a configuration.
- **The BEP-20 gas trap:** moving USDT out of a deposit address needs BNB *in
  that address*. Every sweep is two transactions — fund with BNB, then sweep
  USDT. A dry gas wallet halts every sweep while nothing errors. (§8.3)
- Withdrawals need all three of: an address allowlist, a 24-hour cooldown on
  a newly added address, and a **fresh OTP on the withdrawal itself**. The
  session is never sufficient. (§8.4)
- Money rules from M1 hold unchanged. Balances stay derived; every movement is
  a balanced journal with an `Idempotency-Key`; a JavaScript `number` never
  holds money.
- Commercial numbers go in the `PLATFORM_SETTINGS` registry with bounds, not
  in constructor defaults.
- Commit messages: one line, `feat(context): message`, **no** `Co-Authored-By`.

## Review Focus

1. **A deposit credited twice** because the watcher reprocessed a block after
   a restart and the journal key was not derived from the transaction itself.
   → Task 4.
2. **A deposit silently missed** because the watcher read at the chain head,
   or because it advanced its cursor past a block it had not finished
   processing. → Task 4.
3. **A withdrawal to an address added moments ago**, because the cooldown is
   measured from the wrong timestamp or skipped when the allowlist entry is
   re-saved. → Task 7.
4. **A sweep that spends the gas it was given and leaves the USDT behind**,
   or one that runs while the gas wallet is empty and reports success. → Task 6.
5. **A reversal that credits someone**: the compensating journal must return
   the exact amount to the exact bucket it came from, never to AVAILABLE from
   a bucket that never held it. → Task 5.

## M3 is done when

- A deposit and a withdrawal complete a round trip on BSC testnet.
- The watcher credits on finality, reads only at the finalized head, and
  credits exactly once across a restart.
- A reorged deposit is reversed by a compensating journal (§15 item 6).
- A sweep funds gas first and refuses to run with an empty gas wallet.
- A withdrawal needs the allowlist, the cooldown and a fresh OTP.
- Ledger USDT equals on-chain custody within dust.
- `lint`, `typecheck`, `test`, `test:e2e` and `build` all exit 0.
