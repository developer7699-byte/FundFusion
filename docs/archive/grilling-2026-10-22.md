## Converged spec (buildable)

A **local CLI tool, TypeScript/Node**, that:
1. Reads a **config file** (JSON/YAML): the test command + results folder + artifacts folder.
2. **Wraps and runs** the user's Appium test command (engine-agnostic — Playwright later = different command).
3. Target: **Android emulator**, running tests against the **real trading app** (login: username + password + static OTP).
4. Parses the **JUnit XML** the run produces.
5. **Collects screenshots/logs** the tests wrote to a known folder on failure, links them.
6. Stores each run in **SQLite** (schema designed rerun-ready).
7. Writes a **static HTML report** per run: per-test pass/fail, duration, error, screenshot/log.

**Proof of success:** runs the trading-app suite end-to-end and shows an accurate report (R2 q8).
**Next after MVP:** reruns → flaky detection; cross-run trends; live web dashboard; Playwright (web); then the SaaS build (auth, hosting, billing).

## FINAL SPEC — flaky-aware mobile test runner (prototype)

**One-liner:** A local CLI tool that runs your Appium suite against your Android
trading app and produces a detailed, accurate per-run HTML report — the seed of a
future flaky-test-triage SaaS.

**Stack:** TypeScript / Node.

**Flow:**
1. Read a **config file** (JSON/YAML): test command, results folder, artifacts folder, emulator/device target.
2. **Wrap and run** the user's Appium test command (engine-agnostic → Playwright later = a different command).
3. Target: **Android emulator** *(pending q21 verification; fall back to real device / cloud if the app blocks emulators)*.
4. App under test: the **real Android trading app** — login = username + password + **fixed static OTP** (deterministic).
5. Parse the **JUnit XML** the run emits.
6. **Collect screenshots/logs** the tests wrote to a known folder (tool can't capture them itself) and link them.
7. Store each run in **SQLite** — schema designed **rerun-ready** (a test can hold many results) so flaky detection bolts on later with no migration.
8. Write a **static HTML report** per run: per-test pass/fail, duration, error, screenshot/log.

**First suite:** login → dashboard, plus a couple of read-only flows (portfolio, watchlist). Plus **one deliberately-failing test** as accuracy ground truth.

**Definition of done (prototype):** running the suite produces an HTML report that
shows exactly the one seeded failure and all else passing (R2 q8 + R4 q25).

**Pre-build action items:**
1. Verify the trading app opens on an Android emulator (q21). If not → real device / device cloud.
2. Get a staging/test build with the fixed static OTP and a dedicated test account.
3. Stand up Appium + the Android SDK/emulator locally.

**Roadmap after MVP:** reruns → flaky detection → cross-run trends → live web
dashboard → Playwright (web) → SaaS (auth, hosting, billing). Note: ingest-only
flaky dashboards already exist (Trunk, BuildPulse, Currents, Datadog CI) — the
run+report+trading-app angle is the differentiation to defend.
